# 任务要求

War Room 结算助手的需求说明与分阶段验收标准。

## 1. 目标

为线下桌游《War Room》提供结算辅助，覆盖：

1. 掷骰：按规则计算骰数、分批投掷、结果展示。
2. 伤害分配：按颜色顺序把命中分配到单位。
3. 全局压力记录：各国压力、勋章/民用物资、士气 Zone。

工具定位是“桌面辅助”，不是规则裁判；遇到规则歧义时给出提示而非自动裁决。

## 2. 用户与场景

- 用户：1 名或多名玩家中的结算主持人/指挥官。
- 场景：线下对局，战斗结算、善后与士气阶段；通过 GitHub Pages 在手机/平板/笔记本浏览器打开。

## 3. 总体非功能需求

- 无后端、无登录、无网络请求。
- 快速加载，页面体积小。
- 中文界面；关键数字醒目。
- 响应式布局，适配手机横屏与平板。
- 规则数据可追溯到 `warroom_rules.txt`。

## 4. 分阶段需求

### P0 初始化（已完成）

- 建立目录、文档、开发规范、任务看板与进度日志。
- 搭好 ES Modules 应用壳与规则速查演示。

### P1 掷骰内核（进行中）

目标：完成掷骰的规则计算与展示基础。

功能点：

1. D12 色面模型：白 1、黑 1、红 1、绿 2、蓝 3、黄 4（`warroom_rules.txt §14`）。
2. 支持指定骰数掷骰，校验 0 到 30（`§8`）。
3. 自动按每批 10 骰分批，最后一批可不足 10（`§8.B`）。
4. 结果按颜色归组，并按黄/蓝/绿/红/黑/白顺序展示（`§8.C`）。
5. 随机源可注入，便于确定性自测。

验收标准：

- 输入 0/7/10/11/30/31 时行为正确，超 30 明确报错。
- 固定随机源下，同骰数结果稳定一致。
- 页面能展示批次与颜色统计；结果总数等于请求骰数。

不在本阶段范围：骰数自动计算、优势修正、伤害分配。

### P2 快速战斗伤害分配（待开始）

目标：快速战斗模式下，按“成对/三连”规则直接消灭单位。

功能点：

1. 记录参战各单位类型数量（不含 Troop Transports）。
2. 骰数自动计算：数量 × 战斗值（陆/海两表），含 Port Advantage 的 +2 骰（上限 30）。
3. 每批结果按颜色配对；黑白为万能配对，白骰每单位最多用 1 次；两白不能单独消灭普通单位。
4. Battleship / Carrier 需 3 次命中（三连）消灭。
5. 潜艇：白骰不能用于潜艇；奇数黄色未配对时潜艇逃离（Quick Battle 例外，`§13`）。

验收标准：对照 `warroom_rules.txt §13` 用例逐条手测。

### P3 标准战棋盘模式（待开始）

目标：标准战棋盘的损伤状态、姿态与战后修理。

功能点：

1. 单位按类型/姿态上板，记录 Initial / Lightly Damaged / Damaged / Eliminated / Dive 等状态。
2. 计算 Air Battle Stage 与 Surface Battle Stage 骰数（`§8.A`）。
3. 命中分配规则：受损单位先承受下一击；白骰只打有白色三角的格子（`§8.C`）。
4. Force Advantage 对黑白骰的影响；Cruiser Escort 替伤；Port Advantage（`§7`）。
5. 战斗善后：修理、伤亡表、Troop Transport 损失、领土归属、勋章/压力（`§10`）。

### P4 全局压力记录（待开始）

目标：士气板压力管理。

功能点：

1. 各国压力点数、勋章与民用物资记录。
2. 伤亡点数 → 压力换算（换算表以实体士气板为准，规则 OCR 未给出具体数值，需玩家提供照片/数据）。
3. 勋章/民用物资 1:1 抵消压力；阈值升格 Zone；Zone 惩罚参考（`§12`）。

### P5 战斗善后检查清单（待开始）

把 `§10` 步骤 A-G 做成可勾选流程引导。

### P6 打磨与发布（待开始）

响应式优化、错误提示、数据核对、GitHub Pages 发布检查。
